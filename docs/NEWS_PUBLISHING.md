# Публикация новостей через uNews

## Канонический путь

```text
изменение uDream
    ↓
news/*.md + изображение
    ↓
ветка main на GitHub
    ↓
uNews / GitHub Actions
    ↓
Telegram @uNewsLog
```

uNews автоматически обнаруживает публичный репозиторий `sunpole/udream`, читает новые Markdown-файлы из `news/`, применяет правила безопасности и публикует ещё не опубликованные записи.

Главный workflow находится в репозитории uNews:

```text
sunpole/uNews/.github/workflows/publish-all-news.yml
```

Он запускается по расписанию раз в четыре часа на 7-й минуте (`00:07`, `04:07`, `08:07`, `12:07`, `16:07`, `20:07 UTC`) или вручную. Реальная отправка разрешена только внутри GitHub Actions.

Очередь работает по FIFO: внутри каждого проекта раньше публикуется более ранняя версия, затем среди готовых проектов выбирается самое раннее `queued_at`. За запуск публикуется до 20 новостей с паузой не менее 61 секунды. После каждого успешного Telegram-поста состояние немедленно фиксируется в `data/published.json`; если checkpoint не прошёл, пакет останавливается.

## Обязательный формат

Имя файла:

```text
YYYY-MM-DD-udream-short-title.md
```

Пример YAML:

```yaml
---
type: patch
project: uDream
series: udream
title: Краткое русское название изменения
version: 3.1.1
queued_at: 2026-07-18T20:40:00Z
repo_url: https://github.com/sunpole/udream
web_url: https://sunpole.github.io/udream/
image: 2026-07-18-udream-example.jpg
---
```

Изображение должно находиться рядом с патчноутом. Поле `images` можно использовать для упорядоченного Telegram-альбома; `image` остаётся вариантом для одной картинки.

### Достоверность изображения

- Для заметного пользовательского изменения используется настоящий скриншот именно той версии и функции, о которой сообщает патчноут.
- Нельзя повторно использовать старую или постороннюю картинку только ради заполнения обязательного поля.
- Когда снимок должен сделать пользователь, до merge ему передаются точная ссылка, последовательность действий и область, которую нужно захватить.
- Если функцию нельзя честно показать снимком, используется специально подготовленная схема или ссылка, прямо относящаяся к изменению.
- Перед merge пользователь должен знать, какой текст и какие конкретно изображения уйдут в Telegram.

## Типы публикаций

Наиболее частые значения:

- `release` — готовый заметный релиз;
- `patch` — обычное обновление;
- `bugfix` — исправление ошибки;
- `feature` — новая функция;
- `ui` — изменение интерфейса;
- `docs` — документация и устройство проекта;
- `roadmap` — опубликованный план.

Поле `queued_at` обязательно и содержит точное UTC-время постановки новости в очередь в формате ISO 8601: `YYYY-MM-DDTHH:MM:SSZ`.

## Текст для Telegram

В конце полного патчноута можно добавить блок:

```text
Короткий текст для Telegram:
```

Следующий за ним текст используется как короткая подпись. uNews автоматически добавляет ссылку и обязательные хештеги:

```text
#uDream #тыСон #uNews #Sunpole
```

Для типов `patch`, `docs`, `feature`, `bugfix` и `release` подпись должна явно говорить, что это патч, обновление, релиз или документационное обновление.

## Состояние и ошибки

- Опубликованные записи и Telegram `message_id` хранятся в `data/published.json` репозитория uNews.
- Состояние очереди хранится в `data/health.json`, ошибки — в `data/errors.json`.
- Ошибка ранней новости блокирует только более новые версии того же проекта; остальные проекты продолжают обслуживаться.
- При сбое или заблокированной очереди uNews создаёт один служебный GitHub Issue и закрывает его после восстановления.

## Безопасность

- Секреты Telegram хранятся только в GitHub Secrets репозитория uNews.
- В uDream не добавляются токены, ключи или локальные файлы с секретами.
- Патчноут описывает только реальные изменения из diff.
- Старую Telegram-публикацию не исправляют созданием дубля: для этого в uNews существуют команды обслуживания по известному `message_id`.

## Проверка перед объединением

В uDream:

```bash
node scripts/validate-project.mjs
```

В Pull Request workflow дополнительно запускает `scripts/validate-patchnote-diff.mjs`: если проект изменён, но новый файл патчноута не добавлен, проверка завершается ошибкой.

Точная проверка policy-слоем uNews:

```bash
npm run publish:projects:check -- "../udream/news/<patchnote>.md"
```

Последнюю команду запускают из локальной копии `sunpole/uNews`. Она является dry-run и ничего не отправляет в Telegram.

## Важное следствие merge

Новый корректный патчноут, попавший в публичную ветку `main`, становится кандидатом на автоматическую публикацию. Поэтому перед merge нужно явно сообщить пользователю, какой текст и какое изображение уйдут в `@uNewsLog`.
