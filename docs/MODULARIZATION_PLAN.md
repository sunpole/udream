# План модульного перехода uDream

## Решение

uDream остаётся статическим приложением на JavaScript, GitHub Pages и PWA.

Используются нативные ES Modules, JSDoc и `// @ts-check`. TypeScript, фреймворк, bundler, сервер и runtime-зависимости не вводятся. `package.json` нужен только для запуска встроенного Node.js test runner и не участвует в браузерной сборке.

## Цели

- уменьшить связанность текущего `script.js`;
- защитить поиск, историю и настройки регрессионными тестами;
- сохранить текущее поведение и внешний вид;
- не затрагивать активную базу и сохранённые версии;
- оставить сайт запускаемым напрямую с GitHub Pages без build-шага.

## Этапы

### M1 — поиск и тестовый каркас

- выделить чистые функции поиска и автодополнения в `src/search.js`;
- сохранить различие: автодополнение ищет по началу строки, обычный поиск — по подстроке;
- добавить тесты на режимы `symbol`, `aliases`, `desc`, `tags`, `all`;
- подключить модуль через `<script type="module">`;
- добавить модуль в PWA-кеш.

### M2 — данные и состояние ✅

- загрузка и fallback JSON выделены в `src/data.js`;
- ручный JSON-файл разбирается той же проверяемой функцией;
- начальные значения и чтение сохранённых настроек выделены в `src/state.js`;
- изменяемое UI-состояние остаётся в `script.js` до специализированных этапов M3–M4;
- формат и содержимое базы не меняются.

### M3 — история и локальные настройки

- выделить историю, хлебные крошки и навигацию;
- выделить чтение и запись `localStorage`;
- добавить тесты сериализации и восстановления настроек.

### M4 — представление и локализация

- выделить словарь и переключение языка;
- отделить построение карточки, списков и тегов от поисковой логики;
- сохранить текущую HTML-структуру и визуальное поведение.

### M5 — PWA и стили

- выделить регистрацию service worker;
- только после стабилизации JavaScript решить, действительно ли полезно разделять встроенный CSS;
- провести отдельную проверку установки и offline reload на Android.

## Правила миграции

1. Один этап — один Pull Request и один uNews-патчноут.
2. Этап не должен одновременно менять архитектуру и пользовательское поведение.
3. `versions/v3.0.0/` и `_archive/` не изменяются.
4. При каждом изменении runtime-файлов обновляются список PWA-кеша и `CACHE_NAME`.
5. Перед объединением обязательны `npm test`, `node scripts/validate-project.mjs` и GitHub Actions.
6. TypeScript рассматривается только после M5, если JSDoc и `@ts-check` окажутся недостаточными.
7. Любое отклонение от плана сначала фиксируется в документации.
