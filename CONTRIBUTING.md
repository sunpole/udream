# Участие в разработке uDream

Спасибо за интерес к проекту. uDream остаётся статическим приложением без обязательной сборки и серверной части.

## Перед изменениями

1. Прочитайте `docs/PRODUCT_VISION.md`, `AGENTS.md`, `README.md`, `VERSION.md`, `ROADMAP.md` и документы, относящиеся к задаче.
2. Убедитесь, что задача соответствует текущей версии `v23.8.0` и утверждённой границе следующего этапа.
3. Создайте отдельную ветку от актуальной `main`.
4. Ограничьте Pull Request одной понятной целью.
5. Не изменяйте исторические релизы, сохранённые версии и `_archive/` без отдельного согласования.
6. Не смешивайте без необходимости изменение интерфейса, данных, PWA и архитектуры.

## Данные и переводы

- Не перезаписывайте одну базу, редакцию или версию перевода другой.
- Новый вариант должен иметь отдельную версию и документированное происхождение.
- Сохраняйте стабильные ID, если отдельная миграция не утверждает другое.
- Не удаляйте `data/bd2.json`, `data/db.json`, отчёты и архивные варианты как обычную очистку.
- Изменение активных 4 086 записей требует отдельной data-задачи, проверки и описания миграции.

## Проверки

```bash
npm test
jq empty data/divinity_code_ru.json
jq 'length' data/divinity_code_ru.json
node scripts/validate-project.mjs
node --check script.js
node --check sw.js
python3 -m http.server 8019
```

После запуска локального сервера проверьте основной сайт, поиск, карточку результата и каталог сохранённых версий. Проверки PWA, offline и мобильного поведения указывайте только тогда, когда они действительно выполнены.

## Патчноут

Пользовательски заметное изменение требует патчноута и изображения в `news/`. Следуйте `docs/NEWS_PUBLISHING.md`. После merge в `main` патчноут может быть автоматически опубликован системой uNews в Telegram.

До merge владелец проекта должен знать точный короткий текст и конкретное изображение будущей публикации.

## Сторонний контент

Не добавляйте книги, PDF, длинные цитаты, словарные данные, изображения или переводы третьих лиц без документированного основания. MIT-лицензия проекта относится к оригинальному коду, а не автоматически ко всему содержимому репозитория.

## Pull Request

В описании укажите:

- цель изменения;
- что изменено;
- что увидит пользователь;
- какие проверки выполнены;
- какой патчноут и изображение добавлены;
- затрагиваются ли база, варианты перевода, PWA, права на материалы или Telegram-публикация;
- какая точка отката применяется при проблеме.
